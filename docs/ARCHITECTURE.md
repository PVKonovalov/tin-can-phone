# tin-can-phone — Architecture

Self-hosted multi-user audio calls in the browser. **Hard requirement: no external
infrastructure at runtime** — no public STUN/TURN, no CDNs, no third-party fonts,
analytics or push services. Everything the client needs comes from our server.

## Deployment modes

The same binary and code serve both modes; only configuration differs.

| | Internet | Isolated (LAN / VPN) |
|---|---|---|
| Server address | public ("white") IP + domain name | private IP / internal DNS name |
| TLS | `acme` (Let's Encrypt via `autocert`, only for issuing the cert) or `files` | `selfca` (own CA generated by the server) or `files` |
| Clients reach server | over the Internet | inside the network |

Browsers expose the microphone only in a secure context, so HTTPS is mandatory
in both modes (except `localhost` during development).

## Single binary

```
                ┌──────────────── tincan (Go) ────────────────┐
 browser ──TLS──┤ HTTPS: static (go:embed), REST, /ws signaling│
                │ Room manager (in-memory)                     │
 browser ═UDP═══┤ SFU (Pion WebRTC): one UDP port (UDPMux)     │
         ═TCP═══┤                  + ICE-TCP fallback, same port│
                │ [optional] TURN over TLS (pion/turn)         │
                └──────────────────────────────────────────────┘
```

- **SFU, not mesh.** Each client keeps one `RTCPeerConnection` to the server and
  receives every other participant's audio track through it. Clients never need to
  reach each other, so client-side NAT/CGNAT and blocked mDNS host candidates do
  not matter. The server only forwards RTP (no mixing, no transcoding).
- **No TURN by default.** The server is always reachable (public IP or same
  network) and advertises its own addresses as ICE host candidates
  (`ADVERTISE_IPS`, Pion NAT 1:1). UDP-blocked networks fall back to ICE-TCP.
  TURN over TLS on 443 is an optional last step for proxy-only networks.

## Ports

| Port | Purpose |
|---|---|
| 443/tcp | HTTPS, REST, WebSocket signaling |
| 80/tcp | `acme`: HTTP-01 challenge + redirect; `selfca`: CA install page + redirect; `files`: redirect |
| `MEDIA_PORT`/udp | all WebRTC media (UDPMux) |
| `MEDIA_PORT`/tcp | ICE-TCP fallback |

## Configuration (environment, prefix `TINCAN_`)

| Variable | Meaning |
|---|---|
| `PUBLIC_URL` | external base URL used to build room links (e.g. `https://call.example.com`) |
| `HTTPS_ADDR`, `HTTP_ADDR` | listen addresses (default `:443`, `:80`) |
| `TLS_MODE` | `acme` \| `files` \| `selfca` |
| `TLS_CERT`, `TLS_KEY` | for `files` |
| `ACME_DOMAINS`, `ACME_EMAIL`, `ACME_CACHE_DIR` | for `acme` |
| `SELFCA_DIR`, `SELFCA_SANS` | for `selfca`: where CA/cert live; DNS names and IPs for the server cert |
| `ADVERTISE_IPS` | IPs announced to clients as ICE candidates (public and/or LAN) |
| `MEDIA_PORT` | UDP/TCP media port |
| `MAX_PEERS` | participants per room |
| `ROOM_TTL` | lifetime of an empty room |
| `ALLOWED_ORIGINS` | WebSocket Origin allow-list (defaults to `PUBLIC_URL`) |

## Signaling protocol (WebSocket `/ws?room={roomID}`)

JSON envelope: `{ "type": string, "from": string, "to": string, "payload": object }`.

- The **server assigns `peerId`** and sends it in `welcome` (with the current
  participant list). Clients never choose their own id.
- The server always sets `from`; client-supplied `from` is ignored.
- `peer-joined`, `peer-left`, `peer-state` (muted, display name) are produced by
  the server only.
- `offer` / `answer` / `ice-candidate` are exchanged between a client and the
  SFU. When participants join or leave, the SFU renegotiates (server-initiated
  offers). Clients implement *perfect negotiation* and are the polite side.

## Rooms

- `POST /api/rooms` → `{ roomId, url }`; room IDs carry ≥128 bits of randomness.
- Joining a non-existent room fails with a clear error (no implicit creation).
- Room is removed after `ROOM_TTL` without participants; `MAX_PEERS` enforced.
- Anyone with the link can join (no authentication) — by design, for now.

## Security

WebSocket Origin check, rate limit on room creation, max message size, ping/pong
keep-alive with timeouts, security headers (CSP without external sources), TLS only
for everything except the port-80 bootstrap/redirect handlers.

## Known limitations (state them, don't hide them)

- **No incoming-call notifications** to a closed app: Web Push goes through
  Google/Apple/Mozilla servers, which violates the no-external-infrastructure rule.
- **iOS background:** Safari/PWA suspends the microphone when backgrounded; the
  Media Session API does not prevent this.
- **`selfca`:** the CA root must be installed and trusted on each device (on iOS:
  install the profile, then enable full trust in Settings → General → About →
  Certificate Trust Settings).
