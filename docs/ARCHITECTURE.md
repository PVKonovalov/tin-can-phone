# tin-can-phone — Architecture

Self-hosted multi-user audio calls in the browser. **Hard requirement: no external
infrastructure at runtime** — no public STUN/TURN, no CDNs, no third-party fonts,
analytics or push services. Everything the client needs comes from our server.

## Deployment modes

The same binary and code serve both modes; only configuration differs.

| | Internet | Isolated (LAN / VPN) |
|---|---|---|
| Server address | public ("white") IP + domain name | private IP / internal DNS name |
| TLS | `acme` (Let's Encrypt via `autocert`, only for issuing the cert) or `files` | `selfca` (own CA generated by the server) or `files` |
| Clients reach server | over the Internet | inside the network |

Browsers expose the microphone only in a secure context, so HTTPS is mandatory
in both modes (except `localhost` during development).

## Single binary

```
                ┌──────────────── tincan (Go) ────────────────┐
 browser ──TLS──┤ HTTPS: static (go:embed), REST, /ws signaling│
                │ Room manager (in-memory)                     │
 browser ═UDP═══┤ SFU (Pion WebRTC): one UDP port (UDPMux)     │
         ═TCP═══┤                  + ICE-TCP fallback, same port│
                │ [optional] TURN over TLS (pion/turn)         │
                └──────────────────────────────────────────────┘
```

- **SFU, not mesh.** Each client keeps one `RTCPeerConnection` to the server and
  receives every other participant's audio track through it. Clients never need to
  reach each other, so client-side NAT/CGNAT and blocked mDNS host candidates do
  not matter. The server only forwards RTP (no mixing, no transcoding).
- **No TURN by default.** The server is always reachable (public IP or same
  network) and advertises its own addresses as ICE host candidates
  (`ADVERTISE_IPS`, Pion address rewrite). Clients use no STUN/TURN at all
  (`iceServers: []`); the server learns their addresses as peer-reflexive
  candidates. UDP-blocked networks fall back to ICE-TCP (step 5).
  TURN over TLS on 443 is an optional last step for proxy-only networks.

## Ports

| Port | Purpose |
|---|---|
| 443/tcp | HTTPS, REST, WebSocket signaling |
| 80/tcp | `acme`: HTTP-01 challenge + redirect; `selfca`: CA install page + redirect; `files`: redirect |
| `MEDIA_PORT`/udp | all WebRTC media (UDPMux) |
| `MEDIA_PORT`/tcp | ICE-TCP fallback (step 5) |

## Configuration (environment, prefix `TINCAN_`)

| Variable | Default | Meaning |
|---|---|---|
| `PUBLIC_URL` | | external base URL (`https://host[:port]`): room links, HTTP→HTTPS redirects, default `ALLOWED_ORIGINS` |
| `PUBLIC_HTTP_PORT` | `80` | external plain-HTTP port, used for the `selfca` install link |
| `HTTPS_ADDR`, `HTTP_ADDR` | `:443`, `:80` | listen addresses |
| `TLS_MODE` | (required) | `acme` \| `files` \| `selfca` |
| `TLS_CERT`, `TLS_KEY` | | for `files`; `SIGHUP` reloads them |
| `ACME_DOMAINS`, `ACME_EMAIL`, `ACME_CACHE_DIR` | cache `.data/acme` | for `acme` |
| `SELFCA_DIR` | `.data/selfca` | for `selfca`: where the CA and server certificate live |
| `SELFCA_SANS` | | for `selfca`: DNS names and IPs of the server certificate; each must be inside `SELFCA_PERMITTED` |
| `SELFCA_PERMITTED` | (required in `selfca`) | CA name constraints: DNS suffixes and CIDRs, e.g. `tincan.lan,localhost,10.0.0.0/8,127.0.0.0/8` |
| `MAX_PEERS` | `8` | participants per room (2…32) |
| `MAX_ROOMS` | `1000` | rooms in memory at once |
| `ROOM_TTL` | `30m` | an empty room (including one never joined) is removed after this |
| `ALLOWED_ORIGINS` | origin of `PUBLIC_URL` | WebSocket Origin allow-list, comma-separated; if neither is set, the Origin must be `https://` + the request `Host` |
| `MEDIA_PORT` | `50000` | single UDP port for all media; must differ from the HTTP(S) ports |
| `ADVERTISE_IPS` | auto | IPs announced as ICE host candidates, comma-separated, no duplicates. Unset → all non-loopback, non-link-local unicast host addresses, with a startup warning (set it explicitly) |

Invalid configuration is reported all at once at startup; the effective
configuration is logged (it contains no secrets).

## `selfca`: name-constrained local CA

The CA root is installed and trusted on users' devices, so it must not be able
to vouch for arbitrary sites if `ca.key` leaks. It carries critical X.509 name
constraints built from `SELFCA_PERMITTED`:

- DNS suffixes → `PermittedDNSDomains` (`tincan.lan` permits `tincan.lan` and
  any `*.tincan.lan`). At least one is required (`localhost` counts).
- CIDRs → `PermittedIPRanges`. Constraints apply per name type, so with no CIDR
  the CA gets `ExcludedIPRanges` `0.0.0.0/0` and `::/0` (no IP certificates at all).
- The CA itself has `ExtKeyUsage = serverAuth`, `MaxPathLen 0`.

Constraints are a zone, not exact names: servers can be renamed inside the zone
without a new CA. Changing `SELFCA_SANS` within the zone only re-issues the
server certificate (also re-issued when < 30 days remain; validity 397 days).
`localhost` and `127.0.0.1` are added to the server certificate when permitted.

If an existing CA's constraints differ from `SELFCA_PERMITTED` (including an
unconstrained CA from early dev builds), the server **refuses to start**: delete
`SELFCA_DIR`, restart, and reinstall the new CA on every device. It is never
replaced silently. The port-80 `/install` page shows the CA fingerprint and the
permitted zone and ranges.

## HTTP endpoints

| Endpoint | |
|---|---|
| `GET /` , `GET /room/{id}` | `index.html` (the UI decides what to show; `/room/{id}` with a malformed id → 404) |
| `GET /healthz` | `{"status":"ok","version":...}` |
| `POST /api/rooms` | `201 {"roomId","url"}`; `url` from `PUBLIC_URL`, else `https://` + request `Host`. Rate limit per client IP: 10/min, burst 5 → `429` + `Retry-After`. `MAX_ROOMS` reached → `503` |
| `GET /api/rooms/{id}` | `200 {"roomId","peers","maxPeers"}` or `404` |
| `GET /ws?room={id}` | WebSocket signaling (below) |

API errors are JSON: `{"error": "<code>", "message": "..."}` (codes:
`rate-limited`, `too-many-rooms`, `room-not-found`, `not-found`,
`origin-not-allowed`, `shutting-down`). The client IP is the TCP peer address;
proxy headers are not trusted.

## Rooms

- Room ID: 128 bits from `crypto/rand`, lowercase base32 without padding (26 chars).
  Peer ID: 64 bits, same encoding (13 chars). The server assigns both.
- Joining a non-existent room fails (no implicit creation); `MAX_PEERS` enforced.
- A room is removed `ROOM_TTL` after it became empty (or after creation if
  nobody joined). Occupied rooms never expire.
- Anyone with the link can join (no authentication) — by design, for now.
- In memory only; a restart drops all rooms.

## Signaling protocol (WebSocket `/ws?room={roomId}`)

JSON text frames only. Envelope: `{"type", "from", "to", "payload"}`.
The server always sets `from` (`"server"` or the sender's `peerId`); a
client-supplied `from` is ignored.

Connection flow:

1. The `Origin` header is checked before the upgrade (missing or not allowed → `403`).
2. Unknown or malformed room ID → close `4404` right after the upgrade.
3. The client must send `hello` within 5 s (otherwise `4400`); any other message
   before `hello` → `4400`.
4. The server assigns `peerId`, replies `welcome`, and sends `peer-joined` to
   everyone else. Room full → `4409`.
5. On disconnect for any reason the others get `peer-left`.

| Type | Direction | Payload |
|---|---|---|
| `hello` | C→S | `{displayName}` — control and bidi-override characters stripped, trimmed, must be 1…40 runes (else `4400`) |
| `welcome` | S→C | `{peerId, peers: [{peerId, displayName, muted}], maxPeers}` — `peers` are the others, in join order |
| `peer-joined` | S→C | `{peerId, displayName, muted}` |
| `peer-left` | S→C | `{peerId}` |
| `peer-state` | C→S | `{muted: bool}` (required) |
| `peer-state` | S→C | `{muted}` with `from` = that peer; sent to the others, not echoed |
| `media-join` | C→S | empty — start audio (after the microphone is open); again later = replace the connection |
| `offer` | S→C | `{type: "offer", sdp}`, `from: "sfu"`. **Only the server offers** |
| `answer` | C→S | `{type: "answer", sdp}` |
| `ice-candidate` | C↔S | `RTCIceCandidateInit` (`{candidate, sdpMid, sdpMLineIndex, usernameFragment}`); `null` = end of candidates |
| `error` | S→C | `{code, message}`, codes below |

Media messages (`media-join`, `offer`, `answer`, `ice-candidate`) must have
`to` = `"sfu"` or empty (else `4400`).

Error codes (`error` payload `code`):

| Code | Meaning |
|---|---|
| `unexpected-offer` | a client sent an offer; the server makes all offers |
| `unexpected-answer` | answer with no outstanding offer (e.g. before `media-join`) |
| `media-failed` | the media connection failed, stayed `disconnected` > 15 s, or the answer was invalid; the server closed it. The client may send `media-join` again |
| `media-unavailable` | only from the test stub `room.UnavailableMedia` (no SFU) |

Unknown types, invalid JSON, a missing `type`, binary frames, a second `hello`
or an invalid `peer-state` payload close the connection with `4400`.

Close codes:

| Code | Meaning |
|---|---|
| 1001 | server shutting down |
| 1008 | peer too slow (outbound queue overflow, write timeout) or no pong in time |
| 4400 | malformed or unknown message / message > 64 KiB / no `hello` in time |
| 4404 | room not found |
| 4409 | room full |
| 4429 | message rate exceeded |

Limits and liveness:

- Max client message 64 KiB.
- Per connection: 50 messages/s, burst 100 (every message counts, including `hello`).
- Ping every 15 s; no pong within 10 s → close. Each write has a 5 s timeout.
- Outbound queue of 64 messages per peer. Producers never block: a full queue
  closes that peer (`1008`) instead of stalling the room.
- Graceful shutdown closes every socket with `1001` before the HTTP servers stop.

Media side (`internal/room`), implemented by `internal/sfu`:

```go
type MediaHandler interface {
    PeerJoined(roomID, peerID string, send func(protocol.Envelope) error)
    PeerLeft(roomID, peerID string)
    Signal(roomID, peerID string, msg protocol.Envelope) // media-join / offer / answer / ice-candidate
}
```

`PeerJoined` is called once after `welcome`, `PeerLeft` once after the peer is
removed, and never before `PeerJoined`. `Signal` gets the envelope with `from`
set to the peer and `to = "sfu"`. `PeerJoined` and `Signal` run on the peer's
reader goroutine, so they must return quickly (hand long work off). `send`
never blocks (it queues; a full queue closes that peer asynchronously) and may
be called from any goroutine. `room.UnavailableMedia` is a stub for tests
(answers every media message with `media-unavailable`).

## Media (SFU, `internal/sfu`)

Pion WebRTC, one process-wide `webrtc.API`:

- **Codec:** Opus only (48 kHz, 2 ch, `minptime=10;useinbandfec=1`); default
  interceptors (NACK, RTCP reports, TWCC, stats).
- **Transport:** one UDP socket on `MEDIA_PORT` shared by all connections (ICE
  UDP mux). Every local address is rewritten to `ADVERTISE_IPS` (host
  candidates). The socket only covers the advertised IP families (`udp4`,
  `udp6` or dual-stack): the UDP mux publishes a candidate for every address
  it listens on, and an address of an unadvertised family would otherwise leak
  unchanged. mDNS off; no STUN/TURN on either side; ICE-TCP comes in step 5.

**Model.** One `PeerConnection` per participant who sent `media-join`. Each
publisher's incoming audio is forwarded (RTP only — no decoding, mixing or
transcoding; header extensions stripped since their IDs are per connection)
into a server-owned `TrackLocalStaticRTP` with stream ID = publisher `peerId`
and track ID = `<peerId>-audio`. That track is added to every other
participant's connection, so clients identify a speaker by stream ID. The
logic is the same for 2 or N participants.

**Negotiation — only the server sends offers** (no glare, no perfect
negotiation on the client):

1. The client opens the microphone, then sends `media-join`.
2. The server creates the connection: transceiver 0 is for the client's
   microphone (created `recvonly`; Pion may later reuse it to send another
   participant's audio, which makes it `sendrecv`), plus one track per
   existing publisher. It sends `offer`. The new publisher's track is added to
   everyone else, who get a new offer too.
3. The client applies the offer, puts its microphone on transceiver 0
   (`sender.replaceTrack(mic)`, direction `sendrecv`), and sends `answer`.
4. Trickle ICE both ways; `null` = end of candidates. Server candidates are
   always sent after the offer that started gathering. Client candidates
   arriving before the first answer are buffered.
5. Any later change (someone joins media or leaves) → a new offer. Per
   participant one offer is outstanding at a time: a change during an
   outstanding offer sets a pending flag and the next offer goes out when the
   answer arrives. Removed tracks free their transceiver for reuse, so the SDP
   does not grow with churn.

**Lifecycle.** WebSocket closed / `PeerLeft` → the connection is closed and
the participant's track removed from the others (they are renegotiated). State
`failed`, or `disconnected` for more than 15 s → closed with `media-failed`. A
second `media-join` replaces the old connection.

**Concurrency.** Each room has one worker goroutine that runs all Pion calls
for that room in order; `MediaHandler` methods and Pion callbacks only enqueue
work, so the signaling goroutine never blocks on Pion. Events carry the
connection they belong to and are ignored if it has been replaced. Connections
are closed off the worker (`GracefulClose`). Tests check for goroutine leaks
(`goleak`).

**Client** (`web/rtc.js`): `RTCPeerConnection({iceServers: []})`; incoming
offers and candidates are applied strictly in order; each remote stream plays
in its own `<audio autoplay playsinline>` keyed by stream ID.

## Security

WebSocket Origin check, rate limits on room creation and on messages, max
message size, ping/pong keep-alive, bounded per-peer queues, security headers
(CSP `default-src 'self'` with `connect-src 'self' wss://<host>`, no external
sources; HSTS except in `selfca` mode), TLS 1.2+ for everything except the
port-80 bootstrap/redirect handlers, and a name-constrained CA in `selfca` mode.

## Known limitations (state them, don't hide them)

- **No incoming-call notifications** to a closed app: Web Push goes through
  Google/Apple/Mozilla servers, which violates the no-external-infrastructure rule.
- **iOS background:** Safari/PWA suspends the microphone when backgrounded; the
  Media Session API does not prevent this.
- **`selfca`:** the CA root must be installed and trusted on each device (on iOS:
  install the profile, then enable full trust in Settings → General → About →
  Certificate Trust Settings). Changing `SELFCA_PERMITTED` means a new CA and
  reinstalling it everywhere.
- **Rooms are in memory:** a server restart ends all calls and invalidates links.
- **No reconnection yet:** a dropped WebSocket ends the call for that client;
  WS reconnect, ICE restart and ICE-TCP are step 5.
